* P0: Cache Shell Previews By Query

** Goal

Repeated =Tab=, arrow, =j=, or =k= actions with unchanged input must not rerun
heavy =actra @ --action-preview ...= or =actra @ --mode-preview files ...=
commands.

** Files

| File | Change |
|------+--------|
| =src/actra/activation.cr= | add action preview cache and file preview cache for zsh and bash sections |
| =spec/activation_spec.cr= | assert cache variables/functions are emitted for both shells |

** Design

Use shell-local variables in generated activation script.

For zsh:

#+begin_src sh
typeset -g ACTRA_AT_PREVIEW_CACHE_KEY=""
typeset -g ACTRA_AT_PREVIEW_CACHE_VALUE=""
typeset -g ACTRA_AT_FILE_PREVIEW_CACHE_KEY=""
typeset -g ACTRA_AT_FILE_PREVIEW_CACHE_VALUE=""
#+end_src

For bash:

#+begin_src sh
ACTRA_AT_PREVIEW_CACHE_KEY=""
ACTRA_AT_PREVIEW_CACHE_VALUE=""
ACTRA_AT_FILE_PREVIEW_CACHE_KEY=""
ACTRA_AT_FILE_PREVIEW_CACHE_VALUE=""
#+end_src

Add helper functions in both generated scripts:

#+begin_src sh
_actra_at_action_preview_cached() {
  local action="$1"
  local query="$2"
  local key="action:${action}:${query}"
  if [ "$ACTRA_AT_PREVIEW_CACHE_KEY" = "$key" ]; then
    printf '%s' "$ACTRA_AT_PREVIEW_CACHE_VALUE"
    return
  fi
  ACTRA_AT_PREVIEW_CACHE_VALUE="$(ACTRA_SHELL_HOOK=1 command actra @ --action-preview "$action" "$query" 2>&1)"
  ACTRA_AT_PREVIEW_CACHE_KEY="$key"
  printf '%s' "$ACTRA_AT_PREVIEW_CACHE_VALUE"
}

_actra_at_file_preview_cached() {
  local query="$1"
  local key="files:${query}"
  if [ "$ACTRA_AT_FILE_PREVIEW_CACHE_KEY" = "$key" ]; then
    printf '%s' "$ACTRA_AT_FILE_PREVIEW_CACHE_VALUE"
    return
  fi
  ACTRA_AT_FILE_PREVIEW_CACHE_VALUE="$(ACTRA_SHELL_HOOK=1 command actra @ --mode-preview files "$query" 2>&1)"
  ACTRA_AT_FILE_PREVIEW_CACHE_KEY="$key"
  printf '%s' "$ACTRA_AT_FILE_PREVIEW_CACHE_VALUE"
}
#+end_src

Use helpers inside:

- =_actra_at_show_action_preview=
- =_actra_at_show_mode_preview= when =ACTRA_AT_MODE= is =files=

Invalidate caches when:

- =function '@'= or =function @= executes selected action
- query extraction changes naturally through cache key mismatch
- shell hook initializes

** Acceptance Criteria

- Repeated action cycling with the same query reuses cached action preview.
- Repeated file mode preview with the same query reuses cached file preview.
- Existing candidate-list cache remains intact.
- No =zle -M= usage is introduced.
- =mise exec -- shards build= passes.
- Fast generated-script checks pass:

#+begin_src sh
bin/actra activate bash | bash -n
bin/actra activate zsh > /tmp/actra-zsh-hook.zsh
zsh -n /tmp/actra-zsh-hook.zsh
#+end_src

| =spec/rcl_config_spec.cr= | parse =permissions= RCL block |
| =spec/agent_spec.cr= | CLI option parse behavior if needed |

** Data Model

Add structs:

#+begin_src crystal
enum PermissionMode
  Standard
  Restrictive
  AcceptAll
  Yolo
end

struct ToolPermissionConfig
  getter name : String
  getter allow : Array(String)
  getter ask : Array(String)
  getter deny : Array(String)
  getter ask_external : Bool
end

struct PermissionsConfig
  getter default_mode : PermissionMode
  getter sandbox : Bool
  getter tools : Hash(String, ToolPermissionConfig)
  getter doom_loop_threshold : Int32
end
#+end_src

Add to =Config=:

#+begin_src crystal
getter permissions : PermissionsConfig
#+end_src

** RCL Shape

#+begin_src rcl
permissions do
  default_mode = "standard"
  sandbox = false
  doom_loop_threshold = 3

  tool "read" do
    allow = ["**"]
    ask_external = true
  end

  tool "write" do
    ask = ["**"]
    deny = [".git/**", "**/.env", "**/secrets/**"]
  end
end
#+end_src

* P3: Enforce Permissions in Built-in Tools

** Goal

All built-in tool calls route through one permission checker before executing.

** Files

| File | Change |
|------+--------|
| =src/actra/permission.cr= | new permission checker module |
| =src/actra/agent_tool.cr= | call permission checker before built-in and external tools |
| =src/actra/agent.cr= | build checker from config/options/session |
| =src/actra/session.cr= | persist session allowlist entries |
| =spec/agent_tool_spec.cr= or new =spec/permission_spec.cr= | checker behavior |

** Checker API

#+begin_src crystal
module Actra::Permission
  enum Decision
    Allow
    Ask
    Deny
  end

  struct Request
    getter tool : String
    getter input_key : String
    getter path : String?
    getter command : String?
  end

  class Checker
    def check(request : Request) : Decision
    end
  end
end
#+end_src

** Tool Classification

| Tool | Input key | Path-aware |
|------+-----------+------------|
| =read= | path | yes |
| =ls= | path | yes |
| =grep= | pattern + path | partial |
| =find= | pattern + path | partial |
| =bash= | command | no/path inferred later |
| =write= | path | yes |
| =edit= | path | yes |
| external tools | tool + args JSON | no by default |

** Mode Semantics

| Mode | Behavior |
|------+----------|
| standard | allow read/search/list inside cwd; ask write/edit/bash; ask external paths |
| restrictive | ask unless allow rule matches |
| accept-all | allow inside cwd; ask external paths/destructive commands |
| yolo | allow everything |

Because Actra is non-interactive in many paths, initial =Ask= behavior should be:

- In TTY: print concise prompt and read yes/no.
- Non-TTY: deny with clear error unless =--accept-all= or =--yolo=.

** Acceptance Criteria

- =write= and =edit= no longer execute before permission check.
- =bash= no longer executes before permission check.
- Read-only tools can still work in standard mode inside cwd.
- Non-TTY restrictive write fails safely.
- =--yolo= allows the same write.
- Permission denial returns tool result text, not process crash.
- Existing =--no-tools= and =--tools= behavior still works.

* P4: Session Allowlist, Doom-Loop Detection, Sandbox

** Goal

Complete high-value Zerostack permission parity after core enforcement.

** Files

| File | Change |
|------+--------|
| =src/actra/session.cr= | append/load permission allowlist entries |
| =src/actra/permission.cr= | session allowlist + repeated-call tracking |
| =src/actra/agent_tool.cr= | pass session/checker through registry |
| =spec/permission_spec.cr= | doom-loop and allowlist tests |

** Session Allowlist

Persist entries as JSONL session records:

#+begin_src json
{"type":"permissionAllow","tool":"bash","pattern":"git status","timestamp":"..."}
#+end_src

Load them when opening/continuing a session and apply before config rules.

** Doom-Loop Detection

Track repeated identical permission requests:

| Field | Meaning |
|-------+---------|
| tool | tool name |
| input_key | normalized command/path/pattern |
| count | consecutive repeat count |
| threshold | default =3= |

When threshold is reached:

- standard/restrictive: ask or deny in non-TTY
- accept-all: ask
- yolo: allow but log warning in session

** Sandbox

For =bash= only:

- Add =Sandbox.wrap(command)= abstraction.
- First implementation can support bubblewrap if present.
- If =--sandbox= is requested and bubblewrap is missing, fail clearly.
- Do not silently run unsandboxed when sandbox is explicitly requested.

** Acceptance Criteria

- Approved decision can be reused in same session.
- Repeated identical tool call trips threshold.
- Sandbox explicit failure is clear when =bwrap= is missing.
- =bash= command still captures stdout/stderr/exit status.

* Notes

- Keep RCL shape as real top-level blocks such as =base=, =provider=,
  =permissions=, =server=, and =filetype=. Do not introduce a useless wrapper.
- Preserve existing =--tools= and =--no-tools= semantics while adding
  permissions. Tool availability and tool permission are separate concerns.
- Provider presets should be defaults only. User =provider "...“ do ... end=
  blocks must override built-ins by name.
- Permission prompts must be concise because Actra also runs in shell shortcut
  contexts like =@agent=.
