** Ollama target behavior

- Provider name: =ollama=.
- Default base URL: =http://127.0.0.1:11434/v1= for OpenAI-compatible chat.
- Default API: OpenAI Chat Completions compatible.
- API key: optional/empty.
- Example:

#+begin_src sh
actra --provider ollama --model llama3.1:8b "explain this repo"
@agent --provider ollama --model qwen2.5-coder:7b --prompt code "fix this bug"
#+end_src

** llama.cpp target behavior

- Provider name: =llama.cpp= or =llamacpp= alias.
- Default base URL: =http://127.0.0.1:8080/v1=.
- Default API: OpenAI Chat Completions compatible.
- API key: optional/empty.
- Example:

#+begin_src sh
actra --provider llama.cpp --model local-model "summarize README"
@agent --provider llamacpp --model local --prompt ask "trace config loading"
#+end_src

* Permissions Model Parity

Zerostack has a real permissions model. Actra now has policy-backed permissions in agent tools, including modes, per-tool allow/deny rules, session allowlists, doom-loop detection, and optional sandbox routing.

| Feature | Zerostack | Actra | Status |
|---------+-----------+-------+--------|
| restrictive mode | =-R= | absent | TODO |
| standard mode | default safe/ask policy | absent | TODO |
| accept-all mode | =--accept-all= | absent | TODO |
| yolo mode | =--yolo= | absent | TODO |
| per-tool allow rules | config permission rules | absent | TODO |
| per-tool deny rules | config permission rules | absent | TODO |
| path-aware write/read checks | cwd/external policy | absent | TODO |
| session allowlist | approved decisions persist in session | absent | TODO |
| doom-loop detection | repeated tool call guard | absent | TODO |
| sandboxed bash | =--sandbox= bubblewrap | absent | TODO |

** Actra target permission modes

| Mode | CLI | Behavior |
|------+-----+----------|
| standard | default | allow safe reads/searches in cwd, ask for writes/bash/destructive operations |
| restrictive | =--restrictive= / =-R= | ask for every tool call unless allowed by config |
| accept-all | =--accept-all= | auto-approve operations inside cwd, ask for external paths |
| yolo | =--yolo= | auto-approve all tool calls without prompts |

** Proposed RCL shape

Do not wrap this in a top-level =actra do ... end= block. Keep real RCL blocks.

#+begin_src rcl
permissions do
  default_mode = "standard"
  sandbox = false

  tool "read" do
    allow = ["**"]
    ask_external = true
  end

  tool "write" do
    ask = ["**"]
    deny = [".git/**", "**/.env", "**/secrets/**"]
  end

  tool "bash" do
    allow = ["ls *", "pwd", "git status", "git diff *"]
    ask = ["*"]
    deny = ["rm -rf *", "git reset --hard *"]
  end
end
#+end_src

* Roadmap

** P0: Shell UX stability

| Task | Target | Acceptance |
|------+--------+------------|
| Cache action previews by query/action | activation hook | repeated Tab on same query must not rerun =actra @ --action-preview= |
| Cache file previews by query | activation hook | repeated file-mode redraw must not rerun =actra @ --mode-preview files= |
| Cache action candidate list by query | activation hook | repeated action cycling should reuse loaded candidates |
| Remove zle-only rendering dependency | activation hook | core picker behavior should work without =zle -M= |
| Avoid terminal flicker | activation hook | menu should not appear/disappear on every Tab |

** P1: Local model providers

| Task | Target | Acceptance |

| Document local models | README | examples for =@agent --provider ollama= and =@agent --provider llama.cpp= |
| Add provider specs | specs | payload path and model routing covered |

| Task | Target | Acceptance |

| Task | Target | Acceptance |

| Add worktree commands | CLI or prompt command | create/merge/exit flow exists |

* Current Bottom Line

Actra has solid parity for one-shot agent execution, prompt modes, JSON/RPC
machine modes, sessions, extension hooks, core tools, and shell =@agent= entry.

The next concrete parity targets are:

1. Shell preview caching by query to remove flicker and terminal lag.
2. First-class local model provider presets for Ollama and llama.cpp.
3. A real permissions model with modes, config rules, session allowlists,
   doom-loop detection, and optional sandboxing.
